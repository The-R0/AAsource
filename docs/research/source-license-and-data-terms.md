# AAsource：依赖许可证与上游数据使用条款核查

> 核查日期：2026-08-12  
> 范围：当前 `pyproject.toml` 与 `src/ashare_data` 实际调用的数据源。  
> 本文是工程风险梳理，不是法律意见；若计划商业化、提供 SaaS/API 或批量再分发数据，应让专业律师审阅并向数据权利方取得书面授权。

## 结论

项目自己的原创代码可以上传 GitHub；但“代码仓库可以公开”不等于“依赖可自由商用”，更不等于“上游行情可以抓取、缓存或再分发”。当前风险分布如下：

| 项目 | 风险 | 核心判断 |
|---|---|---|
| 项目原创代码 | 🟢 | 已采用 MIT License；该授权只覆盖项目原创代码，不覆盖第三方数据与服务 |
| pandas / Requests / PyYAML | 🟢 | 都是标准宽松开源许可证，满足保留许可证/声明等条件即可使用和商用 |
| `pytdx==1.72` | 🔴 | PyPI 元数据没有许可证；作者仓库明确称仅供个人研究、不要商业使用，且仓库已归档 |
| 通达信行情服务 | 🔴 | 官方协议限制客户端—服务器交互数据复制及未授权工具接入，社区规则还明确禁止机器人爬取通达信数据 |
| 腾讯财经 `qt.gtimg.cn` | 🔴 | 未找到该端点的官方开放 API 授权；腾讯通用协议对非商业使用、第三方工具获取数据也有限制，但能否逐条适用于该匿名端点尚不确定 |
| 东方财富公开 Web 接口 | 🔴 | 用户协议明确要求未经交易所书面同意不得复制、对外提供全部或部分行情数据，也不得用行情数据开发衍生品 |

当前“无持久化、按请求转接、JSON CLI”比建库和数据打包分发风险低，但不会自动消除对未经授权接口进行程序化获取、商业使用或向第三方转接的条款风险。

## 当前项目实际使用范围

依据仓库代码：

- `pytdx==1.72`：证券列表、日线/分钟 K 线、逐笔成交、除权除息原始信息及交易日判断；连接 `sources.yaml` 中配置的 7709 端口服务器。
- 腾讯财经：`https://qt.gtimg.cn/q=`，用于实时行情和市场横截面。
- 东方财富：`push2*`、`datacenter-web`、`emweb.securities`、`data.eastmoney.com/dataapi` 等 Web 接口，用于板块、涨停池、龙虎榜、大宗交易、资金流、股东和机构持仓等。
- pandas、Requests、PyYAML：数据变换、HTTP 客户端和配置解析。

项目当前不把这些历史数据写入本地数据库，这是良好的风险收敛措施；但 CLI 会把上游记录结构化后返回给调用方，因此仍属于对数据的获取和提供。

## 1. `pytdx==1.72`

### 明确事实

- [PyPI 1.72 官方 JSON 元数据](https://pypi.org/pypi/pytdx/1.72/json)中的 `license` 为空、`license_expression` 为 `null`、`license_files` 为 `null`，没有任何 OSI 许可证声明。
- 同一 PyPI 页面将项目描述为对 TDX 网络协议的纯 Python 实现，并声明代码用于个人网络协议研究，不对外提供服务，还写明“机构请不要使用此代码”。
- [作者官方 GitHub 仓库](https://github.com/rainx/pytdx)已于 2020-04-15 归档；归档声明写明项目为个人学习目的开发，并明确要求不要将代码用于任何商业目的。

### 工程判断

| 行为 | 判断 |
|---|---|
| 在 GitHub 项目中声明依赖名称与版本 | 🟡 通常不等同于复制其源代码，但会让项目运行依赖该受限组件 |
| 下载并个人研究使用 | 🟡 与作者声明的目的相符，但正式授权范围仍不清晰 |
| 将 pytdx 源码或包捆进自己的 wheel/exe | 🔴 没有明确的复制与再分发许可证 |
| 商业使用、生产服务 | 🔴 与作者明确的非商业声明冲突 |
| 修改/派生并重新发布 | 🔴 没有明确许可证授予修改和派生权利 |

因此不能把 pytdx 当作 MIT 依赖，也不能只因它在 GitHub/PyPI 上公开就称其为标准开源软件。

## 2. 通达信服务器与行情数据

当前代码通过 pytdx 直接使用通达信兼容协议和一组 IP:7709 服务器；这不是项目申请并获得密钥的官方开放平台接口。

[通达信官方量化平台文档](https://help.tdx.com.cn/quant/docs/markdown/mindoc-1hdhbmi50d038.html)展示的 HTTP 调用方式要求先开启支持 TQ 的通达信客户端。这至少说明官方公开支持的量化访问有指定客户端与产品路径，不能据此推导未认证的 7709 协议服务器允许第三方转接、批量调用或再分发。

[通达信用户服务协议](https://www.tdx.com.cn/about/yhxy/index.html?tabindex=1)第 10 条限制复制、修改客户端内存数据和客户端—服务器交互数据，限制未经授权的第三方工具接入，并限制制作、发布或传播此类工具，不论是否商业使用。[通达信社区规则](https://www.tdx.com.cn/about/sqgz/index.html)还明确列出“通过机器人爬虫形式抓取通达信数据”，并提示有数据需求应联系官方合作，违规可能被限制 IP、权限或账号。

本轮也未找到通达信官方发布的、明确授权第三方通过 7709 协议抓取并将结果转接给他人的公开许可证。因此应采用保守判断：

| 行为 | 判断 |
|---|---|
| 项目源码公开，包括自己写的 provider 适配器 | 🔴 官方条款对未授权工具接入及制作/传播也有限制；公开前需要专业审阅或官方许可 |
| 低频个人研究调用 | 🟡 未找到明确授权，且还受 pytdx 自身声明约束 |
| 商业调用或作为稳定生产依赖 | 🔴 无授权、无 SLA，pytdx 也明确反对商业使用 |
| 长期缓存/建立历史库 | 🔴 需要核对行情权利方和交易所许可 |
| 向第三方批量转发、售卖或打包行情 | 🔴 未见授权，不应默认允许 |

另外，`sources.yaml` 只列出 IP 地址，未记录服务器所有者、授权来源或用途。发布前应至少把这些端点标成“用户自行配置”，不要把未知归属的服务器清单包装成项目官方可用服务。

## 3. 腾讯财经接口

项目调用 `https://qt.gtimg.cn/q=`，并设置 `Referer: https://stockapp.finance.qq.com/`。本轮没有找到该端点面向第三方开发者的官方 API 文档、许可证或公开商业授权。

[腾讯服务协议](https://edu.tencent.com/agreement.html)包含以下可能相关的通用规则：

- 服务原则上仅供个人、非商业性质使用，除非另有约定；
- 应通过腾讯提供或认可的方式使用服务；
- 未经授权不得使用第三方软件、插件、外挂或系统查看、获取服务内腾讯、合作伙伴或用户的信息和数据，并应遵守 Robots 等规则；
- 未经书面许可不得复制、转载、汇编、发表、建立镜像，或处理软件与服务器之间的交互数据。

因此：

| 行为 | 判断 |
|---|---|
| 开源腾讯响应解析器 | 🟡 解析器本身可以是原创代码，但项目不应声称腾讯授权或官方支持 |
| 未经许可的自动请求/抓取 | 🔴 没有专项授权；通用条款限制第三方软件获取数据，但直接适用性尚待确认 |
| 商业使用 | 🔴 没有专项商业授权；通用条款默认仅限个人非商业使用 |
| 短期内存缓存 | 🟡 有助于降低请求频率，但未找到条款明确授权缓存 |
| 持久化缓存或历史库 | 🔴 无明确授权，可能构成复制和积累数据 |
| 将行情通过公共 API/CLI 向第三方转发 | 🔴 无公开再分发许可 |

需要注意：协议中部分“客户端—服务器交互数据”条款位于基于软件提供服务的章节，是否直接适用于 `qt.gtimg.cn` 匿名 HTTP 行情端点并非百分之百确定。该通用协议未必是此端点唯一或最终适用的条款；但在没有更具体的官方开放 API 协议时，也不能反向推定该端点可自由调用、缓存或再分发。

## 4. 东方财富 Web 接口

项目不是调用一个有开发者协议和 API Key 的正式开放 API，而是调用东方财富网站/客户端所使用的若干公开 Web 端点。

[东方财富用户服务协议](https://about.eastmoney.com/home/protocol)（页面标注生效/更新日期 2025-07-18）明确写明：未经交易所事先书面同意，不得复制行情数据、向任何机构或个人提供全部或部分行情数据，也不得将全部或部分行情数据用于开发衍生品。协议还限制未经书面许可对产品进行逆向工程或使用第三方工具影响产品功能与运行。

[东方财富法律声明](https://about.eastmoney.com/home/disclaimer)同时说明网站内容包括数据，可能涉及第三方权利，东方财富不保证真实性、完整性、及时性或不存在第三方侵权；这不是对第三方抓取、缓存或再分发的授权。

东方财富主站当前 [robots.txt](https://www.eastmoney.com/robots.txt)显示 `Allow: /`。但 Robots 只是爬虫访问指引，不是数据复制、商业使用或再分发的版权/合同许可，并且当前项目实际调用的是多个 API 子域，不能把主站 Robots 规则扩展到所有子域。

| 行为 | 判断 |
|---|---|
| 开源请求参数、字段映射和规范化代码 | 🟡 原创代码可公开，但不构成数据授权 |
| 个人低频、临时查询 | 🟡 风险低于批量抓取，但协议没有授予第三方接口使用权 |
| 批量/高频抓取 | 🔴 无公开授权，并可能触发技术限制或服务终止 |
| 进程内短期缓存 | 🟡 风险收敛措施，不代表获准复制 |
| 长期持久化或构建镜像库 | 🔴 与行情复制限制直接冲突风险较高 |
| 通过 CLI/API 将结果提供给他人 | 🔴 协议明确限制向机构或个人提供全部或部分行情数据 |
| 用原始行情开发衍生数据/产品 | 🔴 协议文字明确要求交易所事先书面同意 |

## “无持久化转接”到底降低了什么风险

当前设计有实际价值：

- 不随 GitHub 仓库、wheel 或 release 发布历史行情数据；
- 不创建东方财富/腾讯/通达信数据镜像；
- 只保留进程内缓存，降低复制规模和数据泄漏面；
- 返回 `source`、`freshness`、`degraded`，避免将第三方数据伪装为项目自有数据。

但它不能解决以下问题：

- 程序化调用方式本身是否得到服务方授权；
- 商业/生产使用是否得到允许；
- JSON CLI 是否在实质上向第三方提供受限行情；
- 对行情计算特征是否落入“衍生品/衍生数据”限制；
- 交易所、信息商或其他权利方对原始行情的权利。

风险通常随部署方式显著变化：

1. **仅发布源码，用户在自己机器上主动调用**：风险相对较低，但仍应披露非官方接口和适用条款。
2. **项目方托管公共 API、Bot 或 SaaS**：项目方主动抓取并向第三方提供数据，风险明显升高。
3. **收费、商业客户、批量导出或历史库**：在没有书面授权前不应推进。

## 发布前建议动作

### 必做

1. **解除 `pytdx` 红色依赖**：优先寻找许可证清晰且允许目标用途的替代实现；如果自行实现协议，也仍需单独解决服务器和行情授权，不能只解决代码许可证。
2. **给原创项目添加许可证**：MIT 或 Apache-2.0 均可，但许可证只覆盖项目原创代码，并在 README 明确排除第三方数据、商标、接口和内容。
3. **增加 `THIRD_PARTY_NOTICES.md`**：记录依赖名称、版本、许可证、官方链接，并把 pytdx 标为无标准许可证/非商业声明，不能伪装为 MIT。
4. **增加数据源免责声明**：明确项目非腾讯、东方财富、通达信官方产品；数据权利归相应权利人；用户须自行确认授权与适用条款；不保证接口稳定、准确或持续可用。
5. **不要发布数据样本的实质性集合**：测试 fixture 仅保留最小合成数据；检查现有 golden files 是否来自真实响应，必要时改为人工合成。
6. **不要宣传自由商用**：在获得依赖和上游书面授权前，不能只凭项目自己的 MIT/Apache 许可证作出这一承诺。

### 强烈建议

7. 将具体 TDX IP、未公开 Web 端点和字段号移出“稳定公共契约”，允许用户自行配置 provider；默认配置不要暗示这些接口受数据方支持。
8. 设置低并发、速率限制、超时、最大窗口和指数退避；不绕过验证码、登录、限流、签名或访问控制。
9. 保持无持久化，不增加历史库、离线数据包、公共代理或服务端共享缓存。
10. 对每个 provider 提供 `terms_url`、`official_api=false`、`commercial_use=unknown/restricted` 等机器可读元数据。
11. 若要商业化，分别联系数据源/交易所购买或确认 API、展示、缓存、衍生计算和再分发许可；尽量换成有合同、API Key、配额和 SLA 的正式数据源。
